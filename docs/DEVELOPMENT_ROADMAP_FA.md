# نقشه راه توسعه «همراه تحصیلی»

این نقشه راه بر اساس معماری فعلی شاخه `main` تنظیم شده است: برنامه کاملاً روی گوشی اجرا می‌شود، داده‌ها محلی هستند و درخواست AI مستقیماً از دستگاه به ارائه‌دهنده منتخب کاربر می‌رود.

## مرحله صفر — تثبیت پایه (در حال انجام در PR #2)

- [x] حذف بک‌اند Flask، Docker و Render
- [x] حذف کلید API از مقادیر کامپایل‌شده و workflowهای ساخت
- [x] افزودن ذخیره‌سازی امن کلید روی Android
- [x] افزودن تنظیمات ارائه‌دهنده و مدل در برنامه
- [x] افزودن اتصال مستقیم HTTPS و خطاهای قابل‌تشخیص
- [x] حفظ راهنمای آفلاین و داده‌های تحصیلی محلی
- [ ] سبز شدن کامل GitHub Actions
- [ ] تست نصب و نگهداری کلید روی گوشی واقعی

## مرحله یک — تکمیل چرخه برنامه‌ریزی

1. ثبت جلسه مطالعه با نام درس، مدت و خودارزیابی تسلط
2. نمایش مجموع زمان مطالعه و روند هفتگی
3. ساخت برنامه مرور از روی تاریخ آزمون
4. امکان تعیین موعد و اولویت برای هر کار
5. گزارش ساده پیشرفت بدون رتبه‌بندی یا ادعاهای غیرمعتبر

## مرحله دو — مرور فاصله‌دار و مربی آموزشی

1. ساخت کارت سؤال/پاسخ از یادداشت‌های خود کاربر
2. مرور زمان‌بندی‌شده و ثبت پاسخ درست/نادرست
3. نمایش موضوعات نیازمند مرور
4. مربی قدم‌به‌قدم آفلاین برای توضیح یک مبحث در چند گام
5. در صورت فعال بودن AI، استفاده از همان اتصال مستقیم کاربر؛ بدون افزودن سرور

## مرحله سه — کیفیت محصول و انتشار

- تست روی چند اندازه صفحه و نسخه Android
- بررسی رفتار ذخیره‌سازی امن در نصب مجدد، به‌روزرسانی و حذف برنامه
- بررسی مجوزهای Android و سیاست حریم خصوصی
- افزودن آیکون و تصاویر فروشگاه
- ساخت APK امضاشده با کلید خارج از مخزن
- انتشار فقط پس از تست واقعی روی دستگاه

## اصولی که نباید نقض شوند

- هیچ بک‌اند، حساب مرکزی، دیتابیس ابری یا کلید API مشترک اضافه نشود.
- هیچ کلید واقعی در کد، GitHub Secrets برای ساخت APK، گزارش CI یا فایل قابل‌انتشار قرار نگیرد.
- قابلیت‌های اصلی برنامه بدون اینترنت قابل استفاده بمانند.
- کاربر کنترل کامل حذف کلید AI و داده‌های محلی خود را داشته باشد.
- هزینه مدل متعلق به حساب ارائه‌دهنده کاربر است و باید شفاف به او اعلام شود.
